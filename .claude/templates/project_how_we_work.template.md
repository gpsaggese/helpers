## Task Rule

- Execute only the tasks that are in the master plan
- Create the GitHub issue for a task before starting it
- Post an ETA in the issue when you take the task, and update it when it changes
  - See "Sync-ups" in `docs/work_organization/all.team_collaboration.how_to_guide.md`

## AI Rule

- Skills to use in each step of the loop: `docs/tools/ai/all.ai_workflows.how_to_guide.md`
- Using AI is fine, but the author must be able to explain every line of the
  AI-written code

## Communication Rule

- GitHub for coding questions and code review
- Google Doc of the project for the research questions, their discussion, and the
  research decisions, with a link from GitHub
  - See `docs/planning/all.document_research.how_to_guide.md`
- Slack for quick pings
- Office hours for the rest

## Paper Rule

- Update the paper when there is new or important research (e.g., once a week), so
  that it reflects the state of the code
- A PR that changes a result, a model, or an assumption fills the Paper and Gdoc
  checklist of `docs/planning/all.document_research.how_to_guide.md`

## Records Rule

- Keep every decision and communication in a non-ephemeral system
- Prefer markdown in the repo, and the Google Doc for the research decisions
- Never keep a decision only in Slack or in a GitHub comment
