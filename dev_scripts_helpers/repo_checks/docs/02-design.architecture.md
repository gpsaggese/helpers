## Goal

- Scripts implement the deterministic checks of the skill
  `helpers_root/.claude/skills/github.cosmetic_check_PR/SKILL.md`
- The same check scripts work on a PR and on the code in a dir
  - E.g., check that the files in a dir are smaller than 512KB
- The scripts also cover the checks of the pre-commit hook
  `helpers_root/dev_scripts_helpers/git/git_hooks/pre-commit.py`, so a PR gets the
  checks that `git commit` runs on the author's machine
  - See `## Pre-Commit Hook Checks`
- The skill and the command line both call the scripts
- Each script points to a dir that holds a repo or a worktree

## Idea: Checks Read the Disk and Ask Git

- A check gets only `--dir` and the paths to look at: nothing else is passed
- A check reads the files from the disk of `--dir`
  - Size, content, and binary detection come from the disk
  - A PR is a worktree of the PR, which the caller provides
  - No code reads git objects
- A check asks git, or `gh`, for a property that the disk does not hold
  - The mode of a file, e.g., `160000` for a submodule pointer
  - The branch checked out in `--dir`
  - The PR of that branch: title, body, base branch
  - The files deleted by the branch
  - The commits of the branch, for `gitleaks`
- No value travels from the selector to the check
  - No `FileInfo`, no `FileSet`
  - No `--pr_url`, `--base`, `--head`, or `--branch_name`
- A check never knows how the paths were selected
  - A selector builds the list of paths to check
  - A check applies its rules to those paths and returns findings
- Flow:
  ```
  --dir, selector flag -> selector -> paths -> check(dir, paths) -> findings -> report
  ```
- The selector flags copy the ones of `invoke git_files`, so they are familiar
- Tests use real temporary dirs and git repos: no mock of the disk or of git

## Selectors

- Exactly one selector per run, `--all_files` by default
- A selector returns paths relative to `--dir` of files that exist on the disk
- `--files "<F1> <F2>"` and `--from_file <FILE>`: an explicit list
  - Same semantics as `invoke git_files`
- `--all_files`: all the files under `--dir`
  - In a git repo, use `git ls-files --cached --others --exclude-standard`
    - It honors `.gitignore` and includes uncommitted files
  - Outside a git repo, use `os.walk`, without following symlinks and skipping
    `.git`
- `--branch`: the files changed by the branch, as a PR shows them
  - Run `git diff --no-renames --name-status <BASE>...HEAD` in the repo root
    - Select the paths that are not `D`
    - A submodule pointer is a path too: the checks ask git for its mode
    - The deleted paths are not on the disk, so they are not selected: CHK2 asks
      git for them
  - `<BASE>` is `origin/<baseRefName>` of the PR of the branch checked out in
    `--dir`, from `get_pr()`
    - `baseRefName` is not `master` in a stacked PR, so the PR is the source of
      truth
    - Without a PR, use `origin/master`, as `invoke git_files` does
  - Use `...`, i.e., the diff from the merge-base, as `--branch_point` does
    - `..` compares with the tip of the base, so an unrebased PR shows the commits
      of the base in reverse
- No guess of the ancestor branch from the git history
  - The nearest branch is a heuristic and fails on stacks
- Optional later, no change to the checks:
  - `--modified` and `--last_commit`, with the semantics of `invoke git_files`
  - `--modified` lets the pre-commit hook call the same checks

## Queries to Git

- The shared module exposes these functions, and the checks call them as needed
  - `get_mode(dir_name, path)`: `git ls-files --stage`, or the stat bits when the
    file is untracked or `--dir` is not in a git repo
  - `get_branch(dir_name)`: `git rev-parse --abbrev-ref HEAD`
  - `get_pr(dir_name)`: `gh pr view` for the branch, or `None`
    - Fields: `number`, `title`, `body`, `baseRefName`, `headRefName`
  - `get_deleted_files(dir_name)`: the `D` paths of the diff of `--branch`
- `gh` stays behind `get_pr()` only, so tests replace one function
- On a detached `HEAD` there is no branch: CHK2 and CHK3 stop with a clear message

## Common Flags

- Every check script takes the same flags, from one function in the shared module
  - `--dir <DIR>`: default `.`
  - One selector: `--files`, `--from_file`, `--all_files`, `--branch`
- A check can add its own thresholds, e.g., `--max_size_kb`
- `--dir` is the place to run and also a filter
  - The repo root is `git -C <DIR> rev-parse --show-toplevel`
  - Only the files under `--dir` are checked
  - A `--dir` outside a git repo allows only `--all_files`, `--files`,
    `--from_file`
  - A worktree and a repo are the same thing for the scripts
- The files are read from disk, so in a dirty client `--branch` checks the edited
  files and not `HEAD`

## Checks by Selector

- CHK1, size and binary files: all selectors, same rule
- CHK2, project directory:
  - `--branch`: all the touched paths, deleted ones included, against
    `<PROJECT_PATH>` built from the branch checked out in `--dir`
  - `--all_files`, `--files`, `--from_file`: `--dir` must match
    `class_project/<course>/<Term><Year>/projects/<name>`
    - Compare `<name>` with the branch only when it is a class PR branch
- CHK3, PR title: two parts
  - Branch name rules: all selectors, from the branch checked out in `--dir`
  - PR metadata rules (title, issue, body): only when `get_pr()` finds a PR,
    otherwise `N/A`
- CHK4a, junk and secrets:
  - File rules: all selectors
  - `gitleaks`:
    - `--branch`: `gitleaks git --log-opts <BASE>..HEAD`
    - `--all_files`: `gitleaks dir <DIR>`
    - `--files` and `--from_file`: `gitleaks dir <FILE>` once per file
- CHK4b, class project layout: all selectors, run on the project dir
  - In a PR: `--dir <WORKTREE>/<PROJECT_PATH>`
- CHK4c, code validity (conflict markers, Python syntax, `ruff`): all selectors
  - The rules read the files from the disk
  - Only the `.py` paths go to the syntax and `ruff` rules

## Pre-Commit Hook Checks

- The hook runs the phases of `_CHECKS` in `pre-commit.py`, on the staged and
  modified files of the current client
- The scripts apply the same rules to the paths of any selector
- Each phase has one of three outcomes:
  - Reused: an existing check already applies the rule
  - New: a new rule in CHK4c
  - Out of scope: the rule is about the act of committing, so a PR or a dir has
    nothing to check

### Mapping of the Phases

- `master`: out of scope
  - It stops a commit on `master`
  - A reviewer never commits to the PR branch
  - A PR from the `master` of a fork fails CHK3 anyway, since the title must be the
    head branch and match `UmdTask<N>_`
- `merged_branch`: out of scope
  - It stops a commit on a branch already merged
  - It reads the local reflog, which a worktree of a PR does not have
- `merge_conflict_markers`: new, CHK4c
  - A line that starts with `<<<<<<< `, `||||||| `, or `>>>>>>> `, or that is
    exactly `=======`
  - Skip the paths that are binary (NUL byte in the first 8KB, or not UTF-8)
- `author`: out of scope
  - It checks that `git config user.email` of the committer is a valid address
  - The value is the config of the reviewer's machine, not a property of the PR
  - Later, optional: the same regex on `git log --format=%ae <BASE>..HEAD`
- `file_size`: reused, CHK1
  - Same limit, 512KB
  - The hook skips `.ipynb` files and CHK1 does not: see
    [`D9`](/helpers_root/dev_scripts_helpers/repo_checks/docs/03-decisions.md#d9-the-pre-commit-hook-is-unchanged)
- `tmp_log_files`: reused, CHK4a
  - Same rule as `_is_tmp_log_file()`: the base name ends with `.log` or starts with
    `tmp.`
  - The hook accepts the deletion of such a file
  - `--branch` never selects a deleted path, so the result is the same
- `ruff_format`: new, CHK4c
  - The hook runs `ruff check --fix` and `ruff format`, which rewrite the files
  - The scripts only report: no write to the worktree
- `words`: out of scope
  - It is commented out in `_CHECKS`, with a TODO that says it is too strict
- `python_compile`: new, CHK4c
  - The hook runs `compileall.compile_file(force=True)`, which writes `__pycache__/`
    in the tree
  - The scripts compile in memory
- `gitleaks`: reused, CHK4a
  - Same rules file: `dev_scripts_helpers/git/gitleaks/gitleaks-rules.toml`
  - The hook scans the staged changes (`--pre-commit --staged`) in a Docker image
  - The scripts scan a range of commits or a dir with the local binary

### Differences from the Hook

- The hook stops at the first failing phase, and the scripts report all the findings
- The hook checks the files in the current client, and the scripts check `--dir`
  - The hook uses `git status --porcelain --untracked-files=no`
  - The selectors of the scripts read `--dir` as described in `## Selectors`
- The hook functions only print and exit: they return no finding
  - A `Why` with a path and a `Fix` needs data, so CHK4c has its own rules, see
    [`D10`](/helpers_root/dev_scripts_helpers/repo_checks/docs/03-decisions.md#d10-the-rules-of-chk4c-are-written-again-not-imported-from-the-hook)

## Output

- Text in the format of `helpers_root/.claude/templates/github_PR_check.template.md`,
  so the skill can paste it
  - The first line is `PASS`, `FAIL`, or `N/A`
  - Each finding has `Why` and `Fix`
- `--json` prints the same data for tools
- Exit code: 1 on `FAIL`, 0 otherwise

## Script Structure

- One script per check, with the `_parse()` / `_main(parser)` structure of
  `helpers_root/.claude/skills/script.rules.md`
- Each script module exposes one public function
  `check_<name>(dir_name, paths, ...)`
  - It reads the files of `paths` from the disk and calls the queries to git
  - The runner imports it, and the tests call it directly
  - A check that needs no file, e.g., CHK3, takes only `dir_name`
- The rules sit in small functions of plain values, e.g.,
  `check_branch_name(name)`, so the tests call them with strings
- The shared module exposes two functions for the scripts, besides the queries
  - `add_selector_args(parser)`: the common flags
  - `get_paths(args)`: run the selector and return the paths
- Thresholds are flags, e.g., `--max_size_kb`, default 512

## Layout

- Selector-independent code and checks:
  `helpers_root/dev_scripts_helpers/repo_checks/`
  - `repo_check_utils.py`: the selectors, the queries to git, the common flags,
    `Finding`, the report formatter
  - `check_files.py`: CHK1
  - `check_risky.py`: CHK4a
  - `check_code.py`: CHK4c
- PR only: `helpers_root/dev_scripts_helpers/github/`
  - `gh_pr_check_title.py`: CHK3
- Class layout: `class_project/`
  - `check_project_dir.py`: CHK2
  - `check_project_layout.py`: CHK4b
- Names drop the `gh_pr_` prefix when the script is not PR specific

## Script Interfaces

### CHK1: File Size and Binary Files

- `helpers_root/dev_scripts_helpers/repo_checks/check_files.py`
  - Fail files over `--max_size_kb` (default 512, i.e., 524288 bytes)
  - Fail binaries: a NUL byte in the first 8KB, the extension list, and
    `.DS_Store`
  - Skip a path that is a dir, e.g., a submodule pointer
  - Count notebooks
    - This is the one difference from `check_file_size()` of the hook, which skips
      `.ipynb` files
  - Print only the failing files
  - Print a `git rm --cached` fix per file

### CHK2: Project Directory

- `class_project/check_project_dir.py`
  - Take the branch from `get_branch(dir_name)`
  - Detect a class PR
  - Build `<PROJECT_PATH>`
  - List the touched paths outside it, from `paths` and `get_deleted_files()`
  - Print a `git mv` fix per path
  - Lives in `class_project/` because it encodes the class layout

### CHK3: PR Title

- `helpers_root/dev_scripts_helpers/github/gh_pr_check_title.py`
  - Get the PR of the branch checked out in `--dir` with `get_pr()`
    - Use `gh issue view` for the issue
  - Checks:
    - Title equal to the head branch
    - The `UmdTask<N>_` pattern and its allowed characters
    - The class pattern with the optional `_<N>` suffix
    - The issue exists
    - The issue title equals the project tag
    - The first body line is `Closes #N` or `Related to #N`, with the same `N`
  - Print a `gh pr edit` fix and never run it

### CHK4a: Junk and Secrets

- `helpers_root/dev_scripts_helpers/repo_checks/check_risky.py`
  - Find:
    - `tmp.*`, `*.log`, `__pycache__/`, `.ipynb_checkpoints/`, `.env`
    - A submodule pointer (`get_mode()` is `160000`): a change with `--branch`, a
      file with the other selectors
  - Run `gitleaks` with the repo rules file, as in `Checks by Selector`
    - The rules file is the one of the hook, `gitleaks-rules.toml`, taken from the
      client that holds the script and never from the checked dir
    - The binary runs locally: the hook uses a Docker image
  - Print `unknown` when `gitleaks` is missing
  - Option: `--skip_gitleaks`
  - The `tmp.*` and `*.log` rule is the one of `check_tmp_log_files()` of the hook

### CHK4b: Class Project Layout

- `class_project/check_project_layout.py`
  - Compare the Docker files with `class_project/project_template`
  - Check that these files exist:
    - `<NAME>_utils.py`
    - The `<NAME>.API` and `<NAME>.example` notebooks, with their paired `.py` files
    - `README.md`
    - `test/test_<NAME>_utils.py`

### CHK4c: Code Validity

- `helpers_root/dev_scripts_helpers/repo_checks/check_code.py`
  - Public function: `check_code(dir_name, paths, ruff_config)`
  - Three rules, which replace the phases `merge_conflict_markers`,
    `python_compile`, and `ruff_format` of the hook
- **Conflict markers**: all the text paths
  - Same rule as `check_merge_conflict_markers()` of the hook
  - Report `<PATH>:<LINE>` and the marker
  - Fix: resolve the conflict and delete the marker lines
- **Python syntax**: only `.py` paths
  - Read the bytes, and call `compile(source, path, "exec", dont_inherit=True)`
    in memory
    - Bytes make `compile()` honor an encoding cookie
    - The code is never run, and no `__pycache__/` is written
  - Report `<PATH>:<LINE>` and the `SyntaxError` message
  - Fix: fix the syntax error
  - The interpreter that runs the script sets the grammar, so a syntax newer than
    the Python 3.11 target can pass
- **`ruff`**: only `.py` paths, read-only
  - Commands:
    ```bash
    > ruff check --no-fix --no-cache --force-exclude --config <RUFF_CONFIG> <FILES>
    > ruff format --check --no-cache --force-exclude --config <RUFF_CONFIG> <FILES>
    ```
  - `--no-cache` avoids a `.ruff_cache/` in the checked tree
  - Skip the files that failed the syntax rule, so an error is reported once
  - Report `<PATH>:<LINE>`, the rule code, and the message for `check`
  - Report the path for `format`
  - Fix: print `ruff check --fix <PATH>` and `ruff format <PATH>`, and never run
    them
  - `ruff` is missing: the rule is `unknown`, as the hook skips it with a warning
- Flags:
  - `--ruff_config <FILE>`: default is `pyproject.toml` of the client that holds the
    script, i.e., `helpers_root/pyproject.toml`
    - A PR can edit its own `pyproject.toml`, so the checked dir does not choose the
      rules
  - `--skip_ruff`
  - `--max_findings <N>`: default 20 per rule, then print the number of the others

### Runner (Optional)

- `class_project/check_all.py`
  - Run the checks above in order
  - Print the full report with the four verdicts
    - The CHK4 verdict is the worst of CHK4a, CHK4b, and CHK4c
    - The template `github_PR_check.template.md` keeps its four verdicts
  - The skill adds only the CHK4 rule reading, which needs judgment
    - The skill drops its rule "Do not run linters": `check_code.py` runs `ruff`
      read-only, on the config of the current client
  - Lives in `class_project/` because it composes the class checks

## Usage Examples

- PR, in the worktree of the PR:
  ```bash
  > check_files.py --dir ~/wt_pr865 --branch
  ```
- Files changed in the current branch:
  ```bash
  > check_files.py --branch
  ```
- Code in a dir:
  ```bash
  > check_files.py --dir class_project/data605/Spring2026/projects/<PROJECT_DIR>
  ```
- A list of files:
  ```bash
  > check_files.py --files "tutorials/a.ipynb tutorials/b.png"
  ```
- Another size limit:
  ```bash
  > check_files.py --dir tutorials --max_size_kb 256
  ```
- Conflict markers, Python syntax, and `ruff` on the PR:
  ```bash
  > check_code.py --dir ~/wt_pr865 --branch
  ```
- The same on a dir, with a config:
  ```bash
  > check_code.py --dir tutorials --ruff_config helpers_root/pyproject.toml
  ```

## Test Strategy

- Use `hunitest.TestCase`, per `helpers_root/.claude/skills/testing.rules.md`
- Checks: write real files in a temporary dir of the scratch space, and call
  `check_<name>(dir_name, paths)`
  - E.g., size filter, binary detection, notebook count
  - E.g., `check_code()`:
    - A file with `<<<<<<< HEAD`, `=======`, and `>>>>>>> branch` fails
    - A binary file with these bytes is skipped
    - A `.py` file with a `SyntaxError` fails, and no `__pycache__/` appears in
      `dir_name`
    - A `.py` file with a `ruff check` finding fails, and one that `ruff format`
      would change fails
    - The file bytes are the same after the run: `ruff` never rewrites
    - A `.py` file with a syntax error is reported once, not by `ruff` too
    - `--ruff_config` wins over a `pyproject.toml` in `dir_name`
    - A missing `ruff` gives `unknown`: put an empty dir in `PATH`
  - E.g., `check_risky.py` and `check_files.py` agree with the hook rules:
    - `tmp.x` and `a.log` fail, and `my.tmp` does not
    - A notebook over the limit fails, which the hook does not
  - For a git property, make a real temporary git repo with `git init` and commits
    - Do not mock git
- Rules: call the small rule functions with plain strings
  - E.g., title parsing, allowed characters, expected path
  - E.g., `is_merge_conflict_marker(line)`: `<<<<<<< HEAD`, `||||||| base`,
    `>>>>>>> br`, and `=======` are markers, while `======== x` and `<<<<<<<` with
    no space are not
- Selectors, on real temporary git repos:
  - `--branch` returns added and modified files, and a submodule pointer
  - `--branch` with `...` ignores a commit added to the base after the branch
    point
  - `--all_files` honors `.gitignore` and includes untracked files
  - `--files` and `--from_file` give the same paths as `--all_files` for the same
    files
- Queries to git:
  - `get_deleted_files()` returns the deleted files
  - `get_mode()` returns `160000` for a submodule pointer
- `gh` is called only in `get_pr()`
  - Tests never call `gh`
  - Tests of the PR rules replace `get_pr()` with a function that returns a fixed
    PR on a real temporary repo
