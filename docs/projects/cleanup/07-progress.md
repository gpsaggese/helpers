9. Docker-in-Docker works on Mac (tested on 2026-11-26)
   - Setup: Mac with Docker 29.10.1, `ubuntu:24.04`, the unmodified
     `install_dind.sh`, and `set_up_docker_in_docker`
   - With `--privileged`, Docker-in-Docker works, so the comment in
     `hserver.enable_privileged_mode()` is wrong for current Docker Desktop
   - Without `--privileged`, the engine dies (`failed to create NAT chain DOCKER`),
     but `set_up_docker_in_docker` still returns 0
   - `vfs` is needed unless `/var/lib/docker` is a volume
     - With a volume, `overlayfs` works, and `python:3.12-slim` uses 196 MB instead
       of 510 MB with `vfs`
   - A named volume keeps the images between runs, but a second engine on the same
     volume fails (`timeout waiting for containerd to start`)
   - The `ulimit -Hn` edit is not needed on Docker 29.10.1
   - `COUNTER=$((counter+1))` (`thin_client_utils.sh:559`) never increments, so the
     timeout never fires
   - The ports of the child containers reach the dev container at `localhost`
   - Sibling mode needs host paths (`-v /app` fails with "not shared from the
     host"), and the socket is root-only (`permission denied` as UID 501)
   - `hserver.get_host_mac_version()` raises `ValueError` for Sonoma (Darwin 23) and
     Big Sur (Darwin 20)
   - The dockerized-tool tests (12 files, 27 `skipif`s) run only on Mac
     (`skipif(not hserver.is_host_mac())`), so the tools were never tested with
     Docker-in-Docker
   - `--privileged` gives all 41 capabilities, no seccomp, and 168 `/dev` entries;
     `cap_add: SYS_ADMIN` allows mounts but not `iptables`
   - `enable_privileged_mode()` changes only two lines of the compose file:
     `privileged: true` and `CSFY_ENABLE_DIND=1`
