# Design: Scripts for `github.cosmetic_check_PR`

- Generated by `.claude/skills/auto_task.create_plan_for_feature/SKILL.md`
- PR list: `HelpersTask1451_Implement_tools_to_automate_PR_review_1.tasks.md`
- Status: draft for review, no code written yet
- Edit this file, then ask to implement

## Goal

- Script 1: create a worktree from a PR URL
- Scripts 2 to N: implement the deterministic checks of the skill
  `helpers_root/.claude/skills/github.cosmetic_check_PR/SKILL.md`
- The same check scripts work on a PR and on the code in a dir
  - E.g., check that the files in a dir are smaller than 512KB
- The skill and the command line both call the scripts
- Each script points to a dir that holds a repo or a worktree

## Idea: Separate the File Selection From the Check

- A PR always gets a worktree, so a check always reads the files from disk
  - No code reads git objects
  - A detached worktree is a normal dir for the scripts
- A check never knows how the files were selected
  - A selector builds the list of files to check
  - A check applies pure rules to that list and returns findings
- Flow:
  ```
  --dir, selector flags -> selector -> FileSet -> check -> findings -> report
  ```
- The selector flags copy the ones of `invoke git_files`, so they are familiar
- Tests need no git for the rules: build a `FileSet` by hand
- Tests of the selectors use real temporary git repos

## FileSet

- `FileSet` holds:
  - `files`: a list of `FileInfo` for the files that exist in the selection
  - `deleted`: the paths removed by the PR, empty unless the selector is a diff
- `FileInfo` holds:
  - `path`: relative to the repo root
  - `size`: bytes, from `os.stat`
  - `mode`: git mode, e.g., `100644`, `160000` for a submodule pointer
  - `is_binary`: bool, a NUL byte in the first 8KB
  - `status`: `A`, `M`, or `-` when there is no diff

## Selectors

- Exactly one selector per run, `--all_files` by default
- `--files "<F1> <F2>"` and `--from_file <FILE>`: an explicit list
  - Same semantics as `invoke git_files`
  - Paths are relative to `--dir`
- `--all_files`: all the files under `--dir`
  - In a git repo, use `git ls-files --cached --others --exclude-standard`
    - It honors `.gitignore` and includes uncommitted files
  - Outside a git repo, use `os.walk`, without following symlinks and skipping `.git`
  - Mode from `git ls-files --stage` for tracked files, from the stat bits otherwise
- `--branch`: the files changed by the branch, as a PR shows them
  - Run `git diff --no-renames --raw <BASE>...<HEAD>` in the repo root
    - It gives status, mode, and path of every changed file, deleted ones included
    - A `D` goes to `deleted`
    - A submodule pointer (mode `160000`) is a `FileInfo` with size 0
  - `--base`: default `origin/master`, as in `invoke git_files`
  - `--head`: default `HEAD`
  - Use `...`, i.e., the diff from the merge-base, as `--branch_point` does
    - `..` compares with the tip of the base, so an unrebased PR shows the commits
      of the base in reverse
- `--pr_url`: a pointer to the PR, same as `--branch` with the base taken from GitHub
  - `gh pr view --json baseRefName,baseRefOid,headRefOid,headRefName`
  - `--base` is `baseRefOid` and `--head` is `headRefOid`
    - `baseRefName` is not `master` in a stacked PR, so the PR is the source of truth
  - Also gives the head branch name, so CHK2 and CHK3 need no `--branch_name`
  - Stop with a clear message when:
    - The commits are missing in `--dir`: run `gh_pr_worktree.py` again
    - `HEAD` of `--dir` is not `headRefOid`: the files on disk are not the PR
- No guess of the ancestor branch from the git history
  - The nearest branch is a heuristic and fails on stacks
  - The PR, or an explicit `--base`, gives the answer
- Optional later, no change to the checks:
  - `--modified` and `--last_commit`, with the semantics of `invoke git_files`
  - `--modified` lets the pre-commit hook call the same checks

## Common Flags

- Every check script takes the same flags, from one function in the shared module
  - `--dir <DIR>`: default `.`
  - One selector: `--files`, `--from_file`, `--all_files`, `--branch`, `--pr_url`
  - `--base <REF>` and `--head <REF>`: used by `--branch` only
  - `--branch_name <NAME>`: the name of the PR branch, for CHK2 and CHK3
    - Needed with `--branch` since the worktree is detached
    - `--pr_url` provides it
- `--dir` is the place to run and also a filter
  - The repo root is `git -C <DIR> rev-parse --show-toplevel`
  - Only the files under `--dir` are checked
  - A `--dir` outside a git repo allows only `--all_files`, `--files`, `--from_file`
  - A worktree and a repo are the same thing for the scripts
- The files are read from disk, so in a dirty client `--branch` checks the edited
  files and not `HEAD`

## Checks by Selector

- CHK1, size and binary files: all selectors, same rule
- CHK2, project directory:
  - `--branch` and `--pr_url`: all the touched paths, deleted ones included,
    against `<PROJECT_PATH>` built from the branch name
  - `--all_files`, `--files`, `--from_file`: `--dir` must match
    `class_project/<course>/<Term><Year>/projects/<name>`
    - Compare `<name>` with `--branch_name` only when it is given
- CHK3, PR title: two parts
  - Branch name rules: all selectors, from `--branch_name`, `--pr_url`, or the
    branch of the repo
  - PR metadata rules (title, issue, body): only with `--pr_url`, otherwise `N/A`
- CHK4a, junk and secrets:
  - File rules: all selectors
  - `gitleaks`:
    - `--branch` and `--pr_url`: `gitleaks git --log-opts <BASE>..<HEAD>`
    - `--all_files`: `gitleaks dir <DIR>`
    - `--files` and `--from_file`: `gitleaks dir <FILE>` once per file
- CHK4b, class project layout: all selectors, run on the project dir
  - In a PR: `--dir <WORKTREE>/<PROJECT_PATH>`

## Output

- Text in the format of `helpers_root/.claude/templates/github_PR_check.template.md`,
  so the skill can paste it
  - The first line is `PASS`, `FAIL`, or `N/A`
  - Each finding has `Why` and `Fix`
- `--json` prints the same data for tools
- Exit code: 1 on `FAIL`, 0 otherwise

## Script Structure

- One script per check, with the `_parse()` / `_main(parser)` structure of
  `helpers_root/.claude/skills/script.rules.md`
- Each script module exposes one public function `check_<name>(file_set, ...)`
  - The runner imports it, and the tests call it directly
- The shared module exposes two functions for the scripts
  - `add_selector_args(parser)`: the common flags
  - `get_file_set(args)`: run the selector and build the `FileSet`
- Thresholds are flags, e.g., `--max_size_kb`, default 512

## Layout

- Selector-independent code and checks:
  `helpers_root/dev_scripts_helpers/repo_checks/`
  - `repo_check_utils.py`: `FileInfo`, `FileSet`, the selectors, the common flags,
    `Finding`, the report formatter
  - `check_files.py`: CHK1
  - `check_risky.py`: CHK4a
- PR only: `helpers_root/dev_scripts_helpers/github/`
  - `gh_pr_worktree.py`: script 1
  - `gh_pr_check_title.py`: CHK3
- Class layout: `class_project/`
  - `check_project_dir.py`: CHK2
  - `check_project_layout.py`: CHK4b
- Names drop the `gh_pr_` prefix when the script is not PR specific

## Script Interfaces

### Worktree

- `helpers_root/dev_scripts_helpers/github/gh_pr_worktree.py`
  - Input: `--pr_url` or `--pr_num`, and `--worktree_dir` (default `~/wt_pr<N>`)
  - The check scripts never create a worktree: the caller runs this script first
  - Strip `/changes`, `/files`, and `/commits` from the URL
  - Fetch `pull/<N>/head` and the base branch (`baseRefName`, which is not always
    `master`) from the PR repo URL
    - Use `--no-recurse-submodules`
    - Save each SHA right after its fetch
  - Compute the merge-base
  - Create the detached worktree, or reuse it when `HEAD` matches
  - Stop with a clear message when the dir exists with another `HEAD`: never delete
  - Print:
    - `worktree`, `head_sha`, `base_sha`, `merge_base`
    - `head_branch`, `base_branch`
    - the `git worktree remove` command
  - Option: `--dry_run`

### CHK1: File Size and Binary Files

- `helpers_root/dev_scripts_helpers/repo_checks/check_files.py`
  - Fail files over `--max_size_kb` (default 512, i.e., 524288 bytes)
  - Fail binaries: `is_binary`, the extension list, and `.DS_Store`
  - Count notebooks
  - Print only the failing files
  - Print a `git rm --cached` fix per file

### CHK2: Project Directory

- `class_project/check_project_dir.py`
  - Needs `--branch_name`, or `--pr_url`, with `--branch`, since the worktree is
    detached
  - Detect a class PR
  - Build `<PROJECT_PATH>`
  - List the touched paths outside it, from `files` and `deleted`
  - Print a `git mv` fix per path
  - Lives in `class_project/` because it encodes the class layout

### CHK3: PR Title

- `helpers_root/dev_scripts_helpers/github/gh_pr_check_title.py`
  - Get the PR from `--pr_url`, or from the PR of the branch checked out in `<DIR>`
    - Use `gh pr view` and `gh issue view`
  - Checks:
    - Title equal to the head branch
    - The `UmdTask<N>_` pattern and its allowed characters
    - The class pattern with the optional `_<N>` suffix
    - The issue exists
    - The issue title equals the project tag
    - The first body line is `Closes #N` or `Related to #N`, with the same `N`
  - Overrides for offline use and tests: `--title`, `--branch_name`, `--body_file`
  - Print a `gh pr edit` fix and never run it

### CHK4a: Junk and Secrets

- `helpers_root/dev_scripts_helpers/repo_checks/check_risky.py`
  - Find:
    - `tmp.*`, `*.log`, `__pycache__/`, `.ipynb_checkpoints/`, `.env`
    - A submodule pointer (mode `160000`): a change with `--branch` and
      `--pr_url`, a file with the other selectors
  - Run `gitleaks` with the repo rules file, as in `Checks by Selector`
  - Print `unknown` when `gitleaks` is missing
  - Option: `--skip_gitleaks`

### CHK4b: Class Project Layout

- `class_project/check_project_layout.py`
  - Compare the Docker files with `class_project/project_template`
  - Check that these files exist:
    - `<NAME>_utils.py`
    - The `<NAME>.API` and `<NAME>.example` notebooks, with their paired `.py` files
    - `README.md`
    - `test/test_<NAME>_utils.py`

### Runner (Optional)

- `class_project/check_all.py`
  - Run the checks above in order
  - Print the full report with the four verdicts
  - The skill adds only the CHK4 rule reading, which needs judgment
  - Lives in `class_project/` because it composes the class checks

## Usage Examples

- PR, with a pointer to the PR:
  ```bash
  > gh_pr_worktree.py --pr_url https://github.com/<OWNER>/<REPO>/pull/865
  > check_files.py --dir ~/wt_pr865 --pr_url https://github.com/<OWNER>/<REPO>/pull/865
  ```
- PR, without `gh` for the files:
  ```bash
  > check_files.py --dir ~/wt_pr865 --branch --base <BASE_SHA> --branch_name <BRANCH>
  ```
- Files changed in the current branch:
  ```bash
  > check_files.py --branch
  ```
- Code in a dir:
  ```bash
  > check_files.py --dir class_project/data605/Spring2026/projects/<PROJECT_DIR>
  ```
- A list of files:
  ```bash
  > check_files.py --files "tutorials/a.ipynb tutorials/b.png"
  ```
- Another size limit:
  ```bash
  > check_files.py --dir tutorials --max_size_kb 256
  ```

## Test Strategy

- Use `hunitest.TestCase`, per `helpers_root/.claude/skills/testing.rules.md`
- Checks: call `check_<name>()` with a `FileSet` built by hand
  - No git, no disk
  - E.g., title parsing, expected path, binary detection, size filter
- Selectors: build real temporary git repos in the scratch space, with `git init`
  and commits
  - Do not mock git
  - `--branch` returns added, modified, and deleted files, and a submodule pointer
  - `--branch` with `...` ignores a commit added to the base after the branch point
  - `--all_files` honors `.gitignore` and includes untracked files
  - `--files` and `--from_file` give the same `FileInfo` as `--all_files` for the
    same files
- Keep `gh` calls behind one thin function that returns the base and head SHAs
  - Tests never call `gh`
  - `--pr_url` tests use a fake of that function on a real temporary repo
- Worktree script: use a local bare repo as the fake `pull/<N>/head` source

## Design Decisions

- Edit the choice if you disagree

### Default Selector

- Default: `--all_files`, since `--dir` alone checks the code in a dir
- Alternative: `--branch` as the default, as `invoke git_files` does
  - A check with no flags would check the diff of the branch
  - It would not run on a dir outside a PR

### Reuse of `hgit.get_files_to_process()`

- Default: write the selectors in `repo_check_utils.py`, and reuse the flag names
  and semantics of `invoke git_files`
  - `get_files_to_process()` hardcodes `origin/master`
  - It drops the deleted files, which CHK2 needs
  - Its `--all_files` does not honor `.gitignore`
  - Its `branch` paths are relative to the repo root, not to `dir_name`
- Alternative: extend `get_files_to_process()` with a base and the deleted files
  - One implementation for all the tools
  - It changes a shared function used by many `invoke` tasks

### Files Included in `--all_files`

- Default: tracked and untracked files, minus the ignored ones
- Alternative: tracked files only
  - This hides a large file that is not yet added

### Location and Names

- Default: new dir `helpers_root/dev_scripts_helpers/repo_checks/` for the scripts
  that are not PR specific
- Alternative: keep all of them in `helpers_root/dev_scripts_helpers/github/` with
  the `gh_pr_` prefix
  - Simpler, but the name says PR for a check that works on a dir

### Worktree Path

- Default: keep `~/wt_pr<N>`, which matches the existing `~/wt_pr865`
- Alternative: the repo convention for other worktrees, a sibling dir
  `<repo>_worktree_<N>`
- `--worktree_dir` overrides the default in both cases

### Location of the Class Checks

- Default: the class checks and the runner live in `class_project/`
- The generic checks live in `helpers_root/`, which other repos also use
- Alternative: all scripts in `helpers_root/`

### Docker Comparison

- Default: add a small public `compare_docker_files()` to
  `class_project/create_project.py` and call it from `check_project_layout.py`
  - No log file in the current client, no `uv` call
  - The function needs `pandas`, which only `create_project.py` loads today
- Alternative: leave `create_project.py` unchanged and copy its small `filecmp`
  logic
  - This duplicates the `_DOCKER_FILES` list

### Runner Script

- Default: write `check_all.py` in the last PR
- Alternative: skip it, and let the skill call each script

### Pre-Commit Hook

- Default: leave `check_file_size()` of the pre-commit hook as it is
  - It skips notebooks, while CHK1 does not
- Alternative: later, add the `--modified` selector and make the hook call
  `check_files.py`
